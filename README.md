# Vehicle Rental Service

Сервис аренды транспорта на Java 21 и Spring Boot 4.1.2.

**Задание №2 по Java Backend.** Проект является продолжением первого задания, в котором HTTP-сервер был реализован с использованием стандартной библиотеки Java.

Во втором задании приложение переведено на Spring Boot с использованием слоистой архитектуры и внедрения зависимостей. Данные по-прежнему хранятся в оперативной памяти.
## Технологии

- Java 21
- Spring Boot 4.1.2
- Spring MVC
- Jakarta Bean Validation
- JUnit 5
- Maven

Используются только разрешённые зависимости:

- `spring-boot-starter-webmvc`
- `spring-boot-starter-validation`
- `spring-boot-starter-test`

## Архитектура

Приложение разделено на несколько слоёв:

- `controller` — обработка HTTP-запросов и формирование ответов.
- `service` — предметная логика и проверка бизнес-правил.
- `repository` — хранение транспорта и клиентов в `HashMap`.
- `model` — модели предметной области.
- `dto` — входные данные HTTP-запросов.
- `exception` — исключения и централизованная обработка ошибок.

Для управления компонентами используются аннотации Spring `@RestController`, `@Service` и `@Repository`.

Зависимости передаются через конструкторы.

## Предметная область

Сервис управляет двумя связанными ресурсами:

- `Vehicle` — транспортное средство.
- `Customer` — клиент, который может арендовать транспорт.

Поддерживаются два типа транспорта:

| Тип | Минимальный возраст | Расчёт стоимости |
|---|---|---|
| Car | 18 лет | Цена за час × часы |
| Scooter | 16 лет | Цена за час × часы + 100 |

Основные правила:

- Один транспорт не может быть арендован несколькими клиентами одновременно.
- Нельзя арендовать транспорт, если возраст клиента не соответствует требованиям.
- Нельзя удалить транспорт, пока он арендован.
- Нельзя удалить клиента с действующей арендой.
- Нельзя изменить возраст клиента так, чтобы нарушить условия действующей аренды.
- При возврате транспорта он снова становится доступным.

## HTTP API

По умолчанию приложение работает по адресу `http://localhost:8080`.

### Клиенты

| Метод | Маршрут | Операция |
|---|---|---|
| GET | `/customers` | Получить всех клиентов |
| GET | `/customers/{id}` | Получить клиента по ID |
| POST | `/customers` | Создать клиента |
| PUT | `/customers/{id}` | Изменить клиента |
| DELETE | `/customers/{id}` | Удалить клиента |

### Транспорт

| Метод | Маршрут | Операция |
|---|---|---|
| GET | `/vehicles` | Получить список транспорта |
| GET | `/vehicles/{id}` | Получить транспорт по ID |
| POST | `/vehicles` | Создать транспорт |
| PUT | `/vehicles/{id}` | Изменить транспорт |
| DELETE | `/vehicles/{id}` | Удалить транспорт |
| POST | `/vehicles/{id}/rent` | Арендовать транспорт |
| POST | `/vehicles/{id}/return` | Вернуть транспорт |
| GET | `/vehicles/{id}/price?hours=2` | Рассчитать стоимость аренды |

Дополнительный маршрут: `GET /ping`.

### Фильтрация

Для `GET /vehicles` поддерживаются необязательные параметры:

- `available=true` — только свободный транспорт.
- `available=false` — только арендованный транспорт.
- `type=car` — только автомобили.
- `type=scooter` — только самокаты.

Параметры можно комбинировать:

```http
GET /vehicles?available=true&type=car
```

## Примеры запросов

### Создание клиента

```bash
curl -i -X POST http://localhost:8080/customers \
  -H "Content-Type: application/json" \
  -d '{"id":1,"name":"Andrey","age":19}'
```

### Создание автомобиля

```bash
curl -i -X POST http://localhost:8080/vehicles \
  -H "Content-Type: application/json" \
  -d '{"id":1,"type":"car","model":"BMW","pricePerHour":500}'
```

### Аренда автомобиля

```bash
curl -i -X POST http://localhost:8080/vehicles/1/rent \
  -H "Content-Type: application/json" \
  -d '{"customerId":1}'
```

### Возврат автомобиля

```bash
curl -i -X POST http://localhost:8080/vehicles/1/return
```

### Расчёт стоимости

```bash
curl -i "http://localhost:8080/vehicles/1/price?hours=3"
```

## Обработка ошибок

Для обработки исключений используется `GlobalExceptionHandler`.

| Статус | Значение |
|---|---|
| 200 OK | Успешный запрос |
| 201 Created | Ресурс создан |
| 204 No Content | Ресурс удалён |
| 400 Bad Request | Некорректные входные данные |
| 404 Not Found | Ресурс или маршрут не найден |
| 405 Method Not Allowed | HTTP-метод не поддерживается |
| 409 Conflict | Нарушение предметных правил |
| 500 Internal Server Error | Внутренняя ошибка сервера |

Пример ответа с ошибкой:

```json
{
  "error": "Транспорт не найден"
}
```

## Запуск приложения

Требуется JDK 21.

### Через IntelliJ IDEA

1. Открыть проект как Maven-проект.
2. Дождаться загрузки зависимостей.
3. Запустить метод `main()` класса `app.Main`.

Spring Boot запускает встроенный Tomcat на порту 8080.

### Через Maven

При наличии установленного Maven:

```bash
mvn clean package
```

Запуск собранного приложения:

```bash
java -jar target/vehicle-rental-1.0-SNAPSHOT.jar
```

В IntelliJ IDEA сборку также можно выполнить через Maven → Lifecycle → `clean`, затем `package`.

Данные находятся в памяти и сбрасываются после перезапуска приложения.

## Тестирование

### Юнит-тесты

Тесты предметной логики находятся в:

`src/test/java/app/service/RentalServiceTest.java`

Проверяются:

- Создание, получение, изменение и удаление ресурсов.
- Уникальность идентификаторов.
- Корректность входных данных.
- Фильтрация транспорта.
- Аренда и возврат транспорта.
- Возрастные ограничения и граничные случаи.
- Защита действующих аренд.
- Расчёт стоимости.
- Обработка отсутствующих ресурсов.

Тесты создают `RentalService` и репозитории непосредственно, без запуска Spring-контекста.

Запуск:

```bash
mvn test
```

Также можно использовать Maven → Lifecycle → `test` в IntelliJ IDEA.

### Проверка HTTP API

В корне проекта находится файл `requests.sh`, содержащий curl-запросы для проверки успешных и ошибочных сценариев.

Перед запуском необходимо перезапустить приложение, чтобы очистить данные в памяти.

В Git Bash:

```bash
bash requests.sh
```

Скрипт проверяет ожидаемые HTTP-статусы и отдельные значения JSON-ответов.

При обнаружении ошибки выводится `FAIL`, а в конце — общее количество успешных и неуспешных проверок.
